# AI Usage and Development Disclosure

This project is designed around deterministic synthetic data and transparent, rule-based decisions.

## AI usage
- An AI assistant may be used to help draft documentation, explain architecture, suggest test cases, and review code structure.
- The synthetic dataset itself is generated by the documented NumPy generator with a fixed seed. No AI model invents ground-truth labels.
- Shrinkage alerts are generated by explicit, inspectable business rules in `src/detection.py`; they are not presented as machine-learning predictions.
- Ground-truth labels are generated from known planted scenario indices and remain in a separate file, excluded from detection input.

## Human verification
Before submission, the project owner should:
1. Run all tests locally.
2. Inspect the generator and rule thresholds.
3. Verify the full-volume profile on available hardware.
4. Review the README and adapt the demo explanation to the final implementation.
5. Confirm that any AI-assisted code is understood and can be explained.

## Limitations
- Synthetic data approximates operational behavior and is not a substitute for real store-specific calibration.
- Current transfer records use group identifiers; a production implementation should add an explicit transfer header/line entity and enforce paired legs.
- The investigation UI stores session events and exports them; production deployment should persist them in a transactional database with authenticated users and role-based access control.
- Detection is a decision-support signal, not proof of theft or employee misconduct.
